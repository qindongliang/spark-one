# 提交与 PR 规范

提交信息默认沿用当前仓库最近中文提交风格，优先使用：

- `功能：...`
- `修复：...`
- `重构：...`
- `更新：...`
- `清理：...`

若所在分支已有明确英文风格约束，可兼容：

- `feat: ...`
- `fix: ...`
- `refactor: ...`
- `update: ...`
- `chore: ...`

默认提交格式：

- 第一行写简洁中文标题，格式为 `类型：一句话概述`
- 标题聚焦“做了什么 + 主要目的”，避免空泛描述
- 标题后空一行，再写正文

正文编写规则：

- 按主题分类分段，分类名使用中文并带冒号，例如 `构建与镜像：`、`后端接口：`、`前端交互：`
- 每个分类下使用短横线列出具体改动，说明改了什么、为什么改
- 若改动影响配置、证书、环境变量、构建链路或兼容性，必须单独写一类说明
- commit 正文不要写 `验证：` 分类
- commit 正文不要写 `已执行 python -m compileall app`、`已执行 frontend 下 TypeScript noEmit 类型检查` 这类验证执行项
- 验证信息保留在 PR 描述或最终回复中，不放入 commit message

推荐示例：

```text
功能：补充 Docker 构建运行链路并修复模型 TLS 证书处理

构建与镜像：
- 新增基础镜像与业务镜像 Dockerfile，固化依赖并收敛运行时。

本地脚本：
- 新增 build/run 脚本，统一本地构建与启动入口。
```

每次提交聚焦一个逻辑变更，例如 API、UI、Schema、文档或重构。

PR 描述建议包含：

- 改动内容与原因
- `.env` / schema 影响说明
- 涉及前端改动时附截图
- 手工验证步骤
